# Ampara — Cyber (PII, taint, IA e painel Risco Cidadão) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar dentro da API Ampara o motor de parsing de PII, o taint analysis com sinks reais, a tradução de falhas por IA, o índice/farol e o painel web "Painel Risco Cidadão", mais as 3 entregas do professor de Cyber (PDF avulso, ZIP só de código, roteiro do vídeo).

**Architecture:** Um `IPiiScanner` (regras por classe via `IPiiDetector`, detecção por chave e por valor) alimenta dois mecanismos: a **marcação na entrada** (middleware registra cada valor sensível num `ITaintScope` por requisição/mensagem MQTT) e o **`ITaintGuard` nos sinks** (logger, resposta não autenticada, erro, Ponte, SignalR, Claude API, banco), que bloqueia/mascara/cifra por valor rastreado **e** por padrão, e grava o rastro `EventoSeguranca` (sem o valor). Um `ITradutorRisco` (Claude) transforma o evento em 2 frases; o índice 0–100 e o farol saem dos eventos de 24 h; o painel React consome `/seguranca/*`.

**Tech Stack:** C# (.NET, net10.0 por `global.json`), ASP.NET Core, EF Core + Npgsql, SignalR, xUnit, `Microsoft.AspNetCore.Mvc.Testing`, EF InMemory (só em testes); React 18.3.1 + Vite 5.4 + TypeScript + Vitest 2.1 + Testing Library; Node 24 (scripts de PDF/prints, `marked`, `playwright-core` com o Edge/Chrome instalado, `highlight.js`); Python 3.13 (gerador do corpus).

**Spec:** `docs/superpowers/specs/2026-11-14-ampara-design.md` (seções 6.3, 7.1, 9, 10, 11) e `docs/superpowers/plans/2026-11-14-00-indice-e-contratos.md` (fonte única de rotas, nomes, formatos, variáveis; vence em conflito). **Files:**

**Interfaces:**
- Produces: `static class Normalizador { string Normalizar(string s); }` — `NormalizationForm.FormKC`, remove U+200B/200C/200D/2060/FEFF, NBSP e espaços finos viram espaço.
- Produces: `static class Chaves { string Normalizar(string chave); }` (minúsculas, sem acento, sem `_ - . espaço`; `palavraSecreta` → `palavrasecreta`).
- Produces: um `IPiiDetector` por classe. Regras:
  - **Cpf**: 11 dígitos com ou sem pontuação, dígitos verificadores válidos, não repetido (`111.111.111-11` não); sem dígito alfanumérico colado nas bordas. Chaves: `cpf`, `documento`.
  - **Imei**: exatamente 15 dígitos (aceita `-`/espaço entre grupos), Luhn válido; 16 dígitos (cartão) não. Chave: `imei`. Desempate da spec: IMEI (15, Luhn) > CPF (11, DV) > Telefone.
  - **Telefone**: com pontuação `(11) 98765-4321`, `+55 11 98765-4321`; só dígitos 11 com DDD 11–99 e 3º dígito 9 se não for CPF válido; 10 dígitos com DDD. Chaves: `telefone`, `celular`, `fone`, `whatsapp`.
  - **Rg**: por valor só no formato `NN.NNN.NNN-D`; por chave (`rg`, `identidade`) qualquer valor.
  - **Email**, **Placa** (`ABC1D23` e `ABC-1234`/`ABC1234`; chave `placa`).
  - **Senha**: por chave (`senha`, `password`, `passwd`, `pwd`, `palavrasecreta`, `segredo`, `authorization`, `cookie`, `xchaveservico`, `xchavepolicia`, `xapikey`) e por valor `(senha|password|pwd)\s*(:|=|é)\s*\S{3,}` (a detecção cobre só o segredo).
  - **Saude**: termos inteiros, sem acento e sem caixa: `laudo, diagnostico, prontuario, atestado medico, receita medica, hiv, depressao, ansiedade, diabetes, cancer, hipertensao, psiquiatrico, esquizofrenia, internacao, tratamento oncologico` e o padrão `CID[- ]?[A-Z]\d{2}`; chaves `laudo, diagnostico, saude, cid, prontuario, medicamento, doenca`.
  - Regra de chave: termo de 2 letras = igualdade; 3 letras = igual/prefixo/sufixo; ≥ 4 letras = contido.
  - Em todas: bordas `(?<![0-9A-Za-z])…(?![0-9A-Za-z])`, para não casar dentro de GUID, JWT, hash ou decimais (`-23.5672490`).
- Produces: `cyber/corpus/corpus.csv` com cabeçalho `id,chave,valor,esperado` (`esperado` = classes separadas por `|`, vazio = negativo).
